RT-READINESS CRITERIA

A system is judged RT-Ready when every single measured CPU wake-up stays within the threshold — one outlier is enough to fail. Jitter is the gap between the scheduled and actual wake time, sampled at 1 ms intervals via nanosleep on a monotonic clock with the thread at SCHED_FIFO priority.

CPU Max Jitter Threshold 100 µs
10 µs 500 µs 1000 µs 1500 µs 2000 µs
< 20 µs PREEMPT_RT patched kernel — hard real-time, motion control, fast PLC
< 100 µs RT-capable — default threshold, suitable for soft real-time tasks
< 500 µs Standard Linux — non-RT use only; interactive and batch workloads
> 500 µs High jitter — VM, aggressive power-saving, or heavy background load
Saved threshold is used on the next test start.
